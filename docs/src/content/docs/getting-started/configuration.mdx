Whatomate uses a TOML configuration file for all settings. By default, it looks for `config.toml` in the current directory; pass `-config /path/to/config.toml` to override.

A complete commented example lives in [`config.example.toml`](https://github.com/trysoft-team/whatomate/blob/main/config.example.toml) at the repository root — copy it to `config.toml` and edit. The reference below documents every section.

## Configuration File

```toml
[app]
name = "Whatomate"
environment = "development"   # development, staging, production
debug = true
encryption_key = ""           # AES-256 key (32+ chars) for encrypting secrets at rest. Required in production.

[server]
host = "0.0.0.0"
port = 8080
read_timeout = 30
write_timeout = 30
base_path = ""                # Set to "/subpath" if behind nginx proxy_pass at a sub-path
allowed_origins = ""          # Comma-separated CORS origins. Empty = allow all (dev only).

[database]
driver = "postgres"           # postgres | mysql | sqlite (sqlserver coming)
# path = "./whatomate.db"     # sqlite only
host = "localhost"            # Use "db" inside Docker compose
port = 5432                   # 3306 for mysql
user = "whatomate"
password = "your-password"
name = "whatomate"
ssl_mode = "disable"          # disable, require, verify-ca, verify-full (mysql also: preferred)
max_open_conns = 25
max_idle_conns = 5
conn_max_lifetime = 300       # seconds

[redis]
host = "localhost"            # Use "redis" inside Docker compose
port = 6379
username = ""                 # Redis 6+ ACL username. Empty = default user.
password = ""
db = 0
tls = false                   # true for managed Redis (Upstash, Redis Cloud)

[jwt]
secret = "change-me-in-production"   # 32+ chars in production
access_expiry_mins = 15
refresh_expiry_days = 1

[storage]
type = "local"                # local | s3
local_path = "./uploads"
s3_bucket = ""
s3_region = ""
s3_key = ""
s3_secret = ""

[whatsapp]
webhook_verify_token = "random-string-change-this"
api_version = "v24.0"
base_url = "https://graph.facebook.com"
app_id = ""                   # Meta App ID for Embedded Signup
app_secret = ""               # Meta App Secret
config_id = ""                # WhatsApp Config ID for frontend login

[cookie]
domain = ""                   # e.g. ".example.com" to share across subdomains. Empty = current host only.
secure = false                # Sets the Secure flag. Auto-forced to true when environment=production.

[rate_limit]
enabled = false               # Master switch
login_max_attempts = 10
register_max_attempts = 10
refresh_max_attempts = 30
sso_max_attempts = 10
window_seconds = 60
trust_proxy = false           # true if behind a reverse proxy (uses X-Forwarded-For / X-Real-IP)
api_max_requests = 200        # Cap across all /api routes, keyed by user (IP when unauthenticated)
api_window_seconds = 60

[tts]
# piper_binary = "/usr/local/bin/piper"
# piper_model = "/opt/piper/models/en_US-lessac-high.onnx"
# opusenc_binary = "opusenc"

[calling]
max_call_duration = 300       # seconds
audio_dir = "./audio"
# hold_music_file = "hold_music.opus"
# ringback_file = "ringback.opus"
transfer_timeout_secs = 120
# per_agent_timeout_secs = 20   # Per-agent ring time before trying the next agent
recording_enabled = true
udp_port_min = 10000
udp_port_max = 10100
# public_ip = "1.2.3.4"        # Required on AWS / cloud where the host doesn't see its public IP
# relay_only = true             # Force all media through TURN

# Configure STUN, TURN, or both. Repeat the [[calling.ice_servers]] block for each.
# [[calling.ice_servers]]
# urls = ["stun:stun.l.google.com:19302"]
# [[calling.ice_servers]]
# urls = ["turn:your-turn.example.com:3478"]
# username = "user"
# credential = "password"

# TURN with a shared secret (coturn "use-auth-secret" / TURN REST mode). When
# `secret` is set, short-lived credentials are generated per request instead of
# using a static username/credential.
# [[calling.ice_servers]]
# urls = ["turn:your-turn.example.com:3478"]
# secret = "your-coturn-static-auth-secret"
# credential_ttl = 86400        # Generated-credential lifetime in seconds (default 86400 = 24h)

[retention]
webhook_delivery_days = 90     # Webhook delivery log; -1 keeps it forever

[default_admin]
email = "admin@admin.com"
password = "admin"
full_name = "Admin"
```

<Aside type="note">
  App-level WhatsApp keys used for Embedded Signup (`app_id`, `app_secret`, `config_id`, `webhook_verify_token`) live in the `[whatsapp]` section of `config.toml`. **Per-organization** settings are not in `config.toml`: WhatsApp account access tokens are configured under **Settings → Accounts**, and AI provider API keys (OpenAI, Anthropic, Google, OpenRouter) under **Settings → Chatbot → AI**.
</Aside>

## Sections in detail

### `[app]`

| Field | Required | Notes |
|---|---|---|
| `name` | no | Display name. Defaults to `"Whatomate"`. |
| `environment` | yes | `development` \| `staging` \| `production`. Sets debug behavior, forces `cookie.secure=true` in production. |
| `debug` | no | Verbose logging. |
| `encryption_key` | **production** | AES-256 key used to encrypt access tokens, SSO client secrets, and other secrets at rest in the DB. Must be 32+ chars. Lose it and you lose stored credentials. |

### `[server]`

| Field | Notes |
|---|---|
| `host`, `port` | Default `0.0.0.0:8080`. |
| `read_timeout`, `write_timeout` | Seconds. |
| `base_path` | Leave empty unless serving at a sub-path (`https://app.example.com/whatomate`) behind a proxy. |
| `allowed_origins` | Comma-separated list, e.g. `"https://app.example.com,https://admin.example.com"`. **Empty allows all origins** — only safe in development. |

### `[database]`

| Field | Notes |
|---|---|
| `driver` | `postgres` (default) \| `mysql` \| `sqlite`. `mysql` covers both MySQL and MariaDB. `sqlserver` is not supported yet; the server refuses to start with it. |
| `path` | SQLite database file. Default `./whatomate.db`, relative to the directory the server is started from — use an absolute path in production. The parent directory must already exist. Only read when `driver = "sqlite"`. |
| `host`, `port`, `user`, `password`, `name`, `ssl_mode` | PostgreSQL or MySQL connection. Ignored for SQLite. `port` defaults to `5432`, or `3306` with `driver = "mysql"`. |

The `max_open_conns` / `max_idle_conns` / `conn_max_lifetime` knobs map directly to `database/sql` pool settings — defaults are tuned for a single API process; raise `max_open_conns` if you run many workers against the same DB.

`ssl_mode` accepts standard `libpq` values: `disable`, `require`, `verify-ca`, `verify-full`. Use `require` or stricter in production. MySQL maps these values to its own TLS settings and also accepts `preferred`; see [MySQL / MariaDB](#mysql--mariadb).

<Aside type="note">
  SQLite suits a single server: the API and its embedded workers share one database file. Separate `whatomate worker` processes on other machines cannot share that file — use PostgreSQL or MySQL for that setup. Redis is still required with SQLite. SQLite search matches case-insensitively only for ASCII letters, so `é` and `É` are treated as different.
</Aside>

### `[redis]`

Required. Used for:
- Job queue (Redis Streams) for campaign sends
- Pub/Sub for campaign-stats fan-out between workers and the API process
- Rate-limit counters (fixed window)
- OAuth state during the SSO login round-trip (5-minute TTL)
- Caches: chatbot settings, flows, keyword rules, AI contexts, WhatsApp accounts, outbound webhooks, user/role permissions, and tags

CSRF protection does **not** use Redis — it is a stateless double-submit cookie check (`whm_csrf` cookie vs. `X-CSRF-Token` header).

Set `tls = true` and provide `username` + `password` for managed services like Upstash or AWS ElastiCache Serverless.

### `[jwt]`

| Field | Notes |
|---|---|
| `secret` | HMAC signing key. **Must be 32+ chars in production.** Rotating invalidates all sessions. |
| `access_expiry_mins` | Default 15. |
| `refresh_expiry_days` | Default 1. |

JWTs are stored in httpOnly cookies — the frontend never sees them.

### `[storage]`

Controls media storage (template samples, uploaded files, call recordings).

- `type = "local"` — files under `local_path` (default `./uploads`). Suitable for single-host deployments. The directory must be writable by the process and persisted (Docker volume). Call recordings land in `local_path/recordings/{org-id}/{call-log-id}.ogg`.
- `type = "s3"` — fill in `s3_bucket`, `s3_region`, `s3_key`, `s3_secret`. Call recordings are uploaded to the bucket.

### `[whatsapp]`

App-level keys used for **Embedded Signup** and Meta Cloud API calls. These are global (not per-org) and **do live in `config.toml`**. Per-organization account access tokens are stored separately via **Settings → Accounts**, not here.

| Field | Notes |
|---|---|
| `webhook_verify_token` | Token Meta echoes back when verifying the `/api/webhook` subscription. Set it to a random string and enter the same value in the Meta App webhook config. |
| `api_version` | Meta Graph API version, e.g. `v24.0`. Defaults to `v18.0` if unset — set it explicitly. |
| `base_url` | Graph API base URL. Defaults to `https://graph.facebook.com`. |
| `app_id` | Meta App ID, used by the frontend Embedded Signup flow. |
| `app_secret` | Meta App Secret. |
| `config_id` | WhatsApp Embedded Signup configuration ID used by the frontend login. |

### `[cookie]`

| Field | Notes |
|---|---|
| `domain` | Set to `.example.com` to share auth cookies across subdomains. Leave empty for single-host. |
| `secure` | The `Secure` cookie flag (HTTPS-only). Automatically forced to `true` when `app.environment = "production"`, regardless of this setting. |

### `[rate_limit]`

Off by default. Turn on with `enabled = true` for any internet-facing deployment.

| Field | Notes |
|---|---|
| `login_max_attempts` | Per IP, per `window_seconds`. |
| `register_max_attempts` | Per IP, per window. Throttles sign-up attempts. |
| `refresh_max_attempts` | Per IP, per window. Higher because legitimate clients refresh often. |
| `sso_max_attempts` | Per IP, per window for `/api/auth/sso/*`. |
| `api_max_requests` | Cap across all `/api` routes, keyed by authenticated user ID (falling back to IP for unauthenticated requests). Defaults to `200` when unset or `0`. |
| `api_window_seconds` | Window for `api_max_requests`. Defaults to `60` when unset or `0`. |
| `trust_proxy` | Set to `true` only if you run behind a trusted reverse proxy (nginx, Cloudflare, ALB) — otherwise clients can spoof their IP via `X-Forwarded-For`. |

Implemented as Redis fixed-window counters. The limiter **fails open**: if Redis is unreachable the error is logged and the request is allowed through.

### `[tts]`

Optional, only used when an IVR step needs to synthesize speech (welcome prompt, menu read-out). All three keys are paths to external binaries / models:

- `piper_binary` — [piper](https://github.com/rhasspy/piper) standalone TTS executable.
- `piper_model` — `.onnx` voice model from [piper-voices](https://huggingface.co/rhasspy/piper-voices). Pair it with the matching `.onnx.json` next to the model. For US English IVR, `en_US-lessac-high` is the highest-quality single speaker; the Docker image ships `en_US-lessac-medium`.
- `opusenc_binary` — `opusenc` from `opus-tools` (`apt install opus-tools` / `dnf install opus-tools`). Defaults to looking up `opusenc` in `PATH`.

The Docker image sets `LD_LIBRARY_PATH=/usr/local/lib` so Piper uses its bundled `libespeak-ng` 1.52 instead of Debian's 1.51. See [Calling → Text-to-Speech](/whatomate/features/calling/#text-to-speech-ivr-greetings).

If unset, IVR flows still work but cannot synthesize new audio prompts on the fly — only pre-rendered Opus files in `calling.audio_dir` will play.

### `[calling]`

Required only if you use WhatsApp voice calling / IVR.

| Field | Notes |
|---|---|
| `max_call_duration` | Hard cap in seconds; calls beyond this are forcibly terminated. Default `300`. |
| `audio_dir` | Where prompt audio files (`hold_music.opus`, `ringback.opus`, IVR prompts) live. Default `./audio`. |
| `hold_music_file`, `ringback_file` | Filenames inside `audio_dir`. `hold_music_file` defaults to `hold_music.opus`; `ringback_file` has no default (hold music is used instead). Both can be overridden per organization under **Settings → Calling**. |
| `transfer_timeout_secs` | How long to wait for an agent to accept a transferred call before falling through. Default `120`. |
| `per_agent_timeout_secs` | Per-agent ring time when routing to a team; if an agent doesn't answer within this window, the next agent is tried. A team's own `per_agent_timeout_secs` wins when set; otherwise this value; otherwise `15`. |
| `recording_enabled` | Records both directions per call and stores an OGG/Opus file. Uses S3 when `s3_bucket` is set; otherwise writes to `[storage] local_path`. |
| `udp_port_min`, `udp_port_max` | RTP/SRTP UDP port range. Whatever range you set must be open in your firewall / security group. Default `10000–10100` gives 100 concurrent streams. |
| `public_ip` | **Required on AWS / GCP / Azure**, where the host's network interface does not have its public IP attached. Pion uses this for ICE candidate generation. |
| `relay_only` | If `true`, advertises only TURN candidates (no host/srflx). Useful when the network is too restricted for direct UDP. |
| `[[calling.ice_servers]]` | One block per STUN/TURN server. STUN-only works in permissive networks; configure TURN for guaranteed connectivity behind strict NAT or corporate firewalls. Each block takes `urls` plus either a static `username`/`credential`, or a `secret` (+ optional `credential_ttl`) for coturn `use-auth-secret` / TURN REST mode — see below. |

For a TURN server running coturn's `use-auth-secret` (TURN REST API) mode, set `secret` to coturn's `static-auth-secret` instead of a static `username`/`credential`. Whatomate then generates short-lived credentials per request (username = expiry timestamp, credential = base64 HMAC-SHA1 of the username keyed by the secret). `credential_ttl` (seconds) sets their lifetime and defaults to `86400` (24h). If both `secret` and a static `username`/`credential` are set, `secret` takes priority.

### `[google]`

Optional. Enables **Connect Google account** under **Settings → Google credentials**, so users can sign in with Google instead of pasting a service-account JSON key.

| Field | Notes |
|---|---|
| `oauth_client_id` | Client ID of a **Web application** OAuth client from Google Cloud Console → APIs & Services → Credentials. |
| `oauth_client_secret` | That client's secret. |

Setup:

1. Create the OAuth client and add the **Authorized redirect URI** shown on the Google credentials page: `<origin><base_path>/api/google-credentials/oauth/callback`. The origin is `server.public_url` when set, otherwise the address you opened Whatomate at.
2. Enable the Google Sheets, Calendar, Docs and Drive APIs in the same project.
3. Configure the OAuth consent screen. Whatomate requests `spreadsheets`, `calendar.events`, `documents`, `drive.file`, `openid` and `email`. None of these is a "restricted" scope, but Sheets, Calendar and Docs are "sensitive": until Google verifies the app, users see an unverified-app warning, at most 100 test users can connect, and in **Testing** publishing status refresh tokens expire after 7 days (users must reconnect).

`drive.file` only covers files Whatomate created or the user opened with it. To work with arbitrary existing Drive files, use a service account and share the files with it.

If `[google]` is unset, an organization's enabled **Google SSO** client (Settings → SSO) is used instead; add the redirect URI above to that client too.

Connected accounts are stored as encrypted `authorized_user` credentials (OAuth client plus refresh token). Reconnecting the same Google account updates the existing credential instead of creating a duplicate.

### `[retention]`

Optional. Controls how long log-style data is kept. Old rows are deleted when the server starts and then once a day.

| Field | Notes |
|---|---|
| `webhook_delivery_days` | Days of [webhook delivery history](/whatomate/features/webhooks/#delivery-retries--concurrency) to keep. Defaults to `90` when unset or `0`. Set a negative value (e.g. `-1`) to keep it forever. Env: `WHATOMATE_RETENTION__WEBHOOK_DELIVERY_DAYS`. |

Dashboard widgets that use the **Webhooks** data source can only report on the days that are still kept.

### `[default_admin]`

The credentials seeded the first time `whatomate server -migrate` runs against an empty user table. Subsequent runs are no-ops. Always change these on first login.

## Environment variables

Any key in `config.toml` can be overridden by an environment variable. The mapping is:

```
WHATOMATE_<SECTION>__<KEY>
```

The separator between the section and the key is a **double underscore (`__`)**; single underscores are preserved as part of a name. This matters because both section names and field names contain single underscores (`default_admin`, `rate_limit`, `ssl_mode`, `s3_bucket`, `app_id`), so collapsing every `_` into a level separator would mangle them (e.g. `rate_limit.enabled` would become `rate.limit.enabled`). The `__` disambiguates the section boundary from underscores inside a name. Examples:

| Variable | TOML field |
|---|---|
| `WHATOMATE_APP__ENVIRONMENT` | `app.environment` |
| `WHATOMATE_APP__ENCRYPTION_KEY` | `app.encryption_key` |
| `WHATOMATE_DATABASE__DRIVER` | `database.driver` |
| `WHATOMATE_DATABASE__PATH` | `database.path` |
| `WHATOMATE_DATABASE__HOST` | `database.host` |
| `WHATOMATE_DATABASE__SSL_MODE` | `database.ssl_mode` |
| `WHATOMATE_REDIS__HOST` | `redis.host` |
| `WHATOMATE_REDIS__TLS` | `redis.tls` |
| `WHATOMATE_JWT__SECRET` | `jwt.secret` |
| `WHATOMATE_STORAGE__S3_BUCKET` | `storage.s3_bucket` |
| `WHATOMATE_RATE_LIMIT__ENABLED` | `rate_limit.enabled` |
| `WHATOMATE_CALLING__PUBLIC_IP` | `calling.public_ip` |
| `WHATOMATE_DEFAULT_ADMIN__PASSWORD` | `default_admin.password` |

Env vars take precedence over the config file, so the typical pattern is to commit a non-secret `config.toml` and inject secrets (`*_PASSWORD`, `*_KEY`, `*_SECRET`, `JWT_SECRET`) via the deployment environment.

<Aside type="caution">
  Array entries (`[[calling.ice_servers]]`) cannot be set via env vars — define them in `config.toml`.
</Aside>

## Database Setup

### PostgreSQL

```bash
# Create database
createdb whatomate

# Or using psql
psql -c "CREATE DATABASE whatomate;"
```

### MySQL / MariaDB

MySQL 8.0.19+ and MariaDB 10.6+ are supported. Set `driver = "mysql"` for both; `port` defaults to `3306`. Create the database with the `utf8mb4` character set:

```sql
-- MySQL
CREATE DATABASE whatomate CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;

-- MariaDB
CREATE DATABASE whatomate CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

The server refuses to start on an older MySQL or MariaDB, or when the database's character set is not `utf8mb4`. Tables use the database's default collation.

`ssl_mode` maps to TLS as follows:

| `ssl_mode` | Connection |
|---|---|
| `disable` (default) | No TLS. |
| `require` | TLS, certificate not verified. |
| `verify-ca`, `verify-full` | TLS. The certificate is verified against the system CAs, and the host name must match it (both values behave like `verify-full`). |
| `preferred` | TLS if the server offers it, otherwise unencrypted. Certificate not verified. |

Any other value stops the server at startup.

Times are stored in UTC, with microsecond precision, whatever the server's time zone.

Every connection runs at the `READ COMMITTED` isolation level, as on PostgreSQL, whatever the server's default (InnoDB's is `REPEATABLE READ`).

<Aside type="note">
  Unique names are case-insensitive under a `_ci` collation: `Sales` and `sales` count as the same canned response, custom role or template name, where PostgreSQL allows both. Other unique text, such as user emails and WhatsApp account names, behaves the same way. Both recommended collations are also accent-insensitive: `José` and `Jose` collide in unique indexes and match each other in equality checks and search. `utf8mb4_unicode_ci` (MariaDB) also ignores trailing spaces when comparing, so `Sales` and `Sales ` are equal.
</Aside>

### SQLite

Set `driver = "sqlite"` and, optionally, `path` in `[database]`. No database server is needed. The file is created the first time the server starts; run once with `-migrate` to create the schema. New files are readable by their owner only (`0600`); an existing file keeps its permissions.

The parent directory of `path` must already exist — the server refuses to start if it does not. The default `./whatomate.db` is relative to the working directory, so use an absolute path in production (for example `/var/lib/whatomate/whatomate.db`).

### Run Migrations

```bash
./whatomate server -migrate
```

Schema is generated from GORM struct tags in `internal/models/`; there are no SQL migration files. Re-running with `-migrate` is safe — it adds new tables/columns and is a no-op for existing ones.

## WhatsApp API Configuration

App-level Embedded Signup keys (`app_id`, `app_secret`, `config_id`, `webhook_verify_token`) live in the `[whatsapp]` section of `config.toml`. Each organization's WhatsApp **account** credentials are **not** in `config.toml` — configure them per organization in the UI:

1. Navigate to **Settings → Accounts**
2. Click **Add Account**
3. Enter:

   | Field | Required | Notes |
   |---|---|---|
   | Name | yes | Label for the account inside Whatomate. |
   | Phone Number ID (`phone_id`) | yes | From Meta Business Suite. |
   | Business Account ID (`business_id`) | yes | WABA ID from Meta Business Suite. |
   | Access Token | yes | Generated in Meta for Developers. Encrypted at rest. |
   | App ID | no | Meta App ID for this account. |
   | App Secret | no | Used to verify `X-Hub-Signature-256` on inbound webhooks. Encrypted at rest. Verification only runs when both the header is present **and** the matching account has an App Secret — set it, or inbound webhooks are accepted unverified. |
   | Webhook Verify Token | no | An additional accepted verify token. `GET /api/webhook` checks the global `whatsapp.webhook_verify_token` first, then any account's token. |
   | API Version | no | Per-account override of `whatsapp.api_version`. |

   Accounts also carry the toggles `is_default_incoming`, `is_default_outgoing`, `auto_read_receipt` and `business_calling_enabled`, plus an optional `default_chatbot_flow_id` used when an inbound message does not match another flow's trigger keywords.

<Aside type="caution">
  Access tokens are encrypted at rest using `app.encryption_key`. If you haven't set that, tokens are stored in plaintext.
</Aside>

## Building

### Development

```bash
make build    # Backend only (no frontend embedded)
```

For development, run the backend and frontend separately:

- Backend: `make run-migrate` (or `./whatomate server -migrate`)
- Frontend: `cd frontend && npm run dev`

The Vite dev server proxies `/api` to `:8080`.

### Production

```bash
make build-prod    # Single binary with embedded frontend
```

| Command | Frontend | Use Case |
|---|---|---|
| `make build` | not embedded | Development |
| `make build-prod` | embedded | Production |
| `make release-snapshot` | embedded | Every release archive (Linux, macOS, Windows, FreeBSD) into `dist/`, without publishing |

Releases are published from the `master` branch; see [How Releases Are Published](/whatomate/getting-started/quickstart/#how-releases-are-published).

## CLI Reference

```bash
./whatomate <command> [options]
```

| Command | Description |
|---|---|
| `server` | Start the API server (with optional embedded workers) |
| `worker` | Start background workers only (no API server) |
| `version` | Show version information |
| `help` | Show help message |

### `server` options

```bash
./whatomate server [options]

  -config string    Path to config file (default "config.toml")
  -migrate          Run database migrations on startup
  -workers int      Number of embedded workers, 0 to disable (default 1)
```

### `worker` options

```bash
./whatomate worker [options]

  -config string    Path to config file (default "config.toml")
  -workers int      Number of workers to run (default 1)
```

## Deployment Scenarios

### All-in-One

API and workers in a single process — simplest, fine up to moderate campaign volume:

```bash
./whatomate server
```

### Separate API and Workers

Disable embedded workers on the API host:

```bash
./whatomate server -workers=0
```

Run workers on separate machines:

```bash
./whatomate worker -workers=4
```

Both API and worker processes need access to the same database (PostgreSQL or MySQL) and Redis. SQLite does not support this setup.

### Docker Compose

The bundled [`docker-compose.yml`](https://github.com/trysoft-team/whatomate/blob/main/docker-compose.yml) at the repository root builds the image from source and runs three services — `app`, `db` (postgres:17-alpine) and `redis` (redis:7-alpine). The `app` service runs `server -migrate -config /app/config.toml`, i.e. API plus one embedded worker.

```bash
docker compose up -d --build
```

It mounts `./config.toml` read-only into the container and `./uploads` read-write, and reads `.env` for `TZ` and the `POSTGRES_*` credentials (copy [`.env.example`](https://github.com/trysoft-team/whatomate/blob/main/.env.example) to `.env`). `TZ` matters — IVR timing nodes evaluate business hours in the container's local time. With `calling.recording_enabled = true` and local storage, call recordings are written under `uploads/recordings/`.

There is no separate `worker` service in the bundled file. To scale workers, either raise `-workers` on the `app` command, or add your own service running `worker -workers=N` against the same `db` and `redis`.

## Production Recommendations

- Set `app.environment = "production"` and `app.debug = false`.
- Set `app.encryption_key` to a 32+ char random string. Back it up — losing it means losing all stored credentials.
- Use strong, unique values for `jwt.secret` (32+ chars).
- Set `database.ssl_mode = "require"` (or stricter).
- Configure `redis.password` (and `redis.username` for ACL) and enable `redis.tls = true` for managed Redis.
- Enable `rate_limit.enabled = true` and set `rate_limit.trust_proxy` to match your reverse proxy.
- Restrict `server.allowed_origins` to your actual frontend hostnames.
- For voice calling: set `calling.public_ip` on cloud hosts, ensure UDP `udp_port_min`–`udp_port_max` is open in your security group, configure at least one `[[calling.ice_servers]]` (TURN strongly recommended for traversal across strict NATs).
- Terminate TLS at a reverse proxy (nginx, Caddy, or a cloud load balancer) — the binary serves HTTP only.
- Run API and workers as separate processes so a stuck campaign send doesn't block API responses.
